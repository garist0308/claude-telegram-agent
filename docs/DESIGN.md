# Как это устроено и почему

Обозначения:

- **РУЧНОЙ ШАГ** — то, что физически нельзя сделать без тебя: код из
  приложения Telegram, пароль двухфакторной авторизации, вход на
  my.telegram.org.

---

## 1. Что получится

Ты пишешь Claude: «Отправь Маше, что встреча переносится на завтра». Claude
находит Машу среди диалогов твоего аккаунта и отправляет ей сообщение — с
твоего личного аккаунта, не с бота. Если подходящих контактов ноль или больше
одного, ничего не отправляется: Claude говорит об этом и показывает кандидатов.

Ты также можешь попросить прочитать переписку («что мне писал Коля за
последнюю неделю?») — агент пройдёт историю диалога постранично, расшифрует
голосовые и видео-кружки в текст и соберёт из этого ответ.

---

## 2. Как это устроено

```
Ты: «Отправь Маше, что встреча переносится на завтра»
        │
        ▼
┌───────────────────────────────────────────────────────────────┐
│ Claude (агент)                                                 │
│  разбирает фразу → получатель «Маше», текст «Встреча…»        │
│  решает, однозначен ли получатель                             │
└───────────────────────────────────────────────────────────────┘
        │  MCP, транспорт stdio (локальный процесс, без сети)
        ▼
┌───────────────────────────────────────────────────────────────┐
│ claude-telegram-agent — node-процесс на этой машине            │
│                                                                 │
│  telegram_whoami            чей аккаунт подключён              │
│  telegram_list_dialogs      диалоги: id, title, username       │
│  telegram_find_recipient    «Маше» → кандидаты + уверенность   │
│  telegram_send_message      отправка текста и ответов           │
│  telegram_read_messages     чтение истории, расшифровка голоса │
│  telegram_send_file         отправка файла с компьютера        │
│  telegram_download_file     скачивание файла из сообщения      │
│                                                                 │
│  проверки перед отправкой, чтением и скачиванием:              │
│   • сверка expect_title с настоящей сущностью Telegram         │
│   • только человек, только личный диалог                       │
│   • 1 отправка / 5 с, 20 / час; файл не больше 50 МБ            │
│   • запись отправок в ~/.telegram-mcp/sent.log                 │
└───────────────────────────────────────────────────────────────┘
        │  MTProto, сессия твоего личного аккаунта
        ▼
Telegram → сообщение/файл уходит от твоего имени,
           либо история диалога приходит обратно агенту
```

Порядок работы на отправку: запрос → `telegram_find_recipient` → если
кандидат ровно один, `telegram_send_message`/`telegram_send_file` с его
`peer` и `title` → подтверждение. Если кандидатов ноль или больше одного —
ничего не отправляется, агент спрашивает тебя.

Порядок работы на чтение: тот же поиск получателя → `telegram_read_messages`
с `peer` и `expect_title` → если нужна вся история, а не только последние
сообщения, агент вызывает инструмент повторно с `offset_id` от предыдущего
ответа, пока история не закончится.

## 3. Что нужно от тебя: три шага, около трёх минут

### Шаг 1. `api_id` и `api_hash`

**РУЧНОЙ ШАГ.** Открывается и с телефона, можно сделать заранее.

1. <https://my.telegram.org>, вход по номеру того аккаунта, с которого будешь
   писать. Код придёт в приложение Telegram.
2. **API development tools** → заполнить форму (название и платформа — любые).
3. Со страницы понадобятся **App api_id** (число) и **App api_hash** (32
   символа).

Это идентификаторы приложения, а не пароль от аккаунта. Вводятся один раз.

### Шаг 2. Вход

```bash
npm run login
```

Скрипт спросит по очереди: `api_id`, `api_hash`, номер телефона, код из
Telegram и — если включена двухфакторная авторизация — пароль 2FA. Ввод
`api_hash` и пароля не отображается на экране.

Код и пароль ты вводишь сам, в терминале. Агент их не видит и не вводит: код
приходит тебе в приложение, а пароль 2FA — это пароль, его агенту передавать
незачем. Скрипт и написан так, что откажется работать не из интерактивного
терминала — то есть передать код или пароль через агента физически нельзя.

На выходе — `~/.telegram-mcp/credentials.json` с правами `0600`, вне
репозитория. Строка сессии на экран не печатается.

### Шаг 3. Сказать агенту, что готово

Дальше работает так:

```
Отправь Маше, что встреча переносится на завтра
```

Если захочешь сначала посмотреть без реальной отправки, скажи — включи сухой
прогон (`TELEGRAM_MCP_DRY_RUN=1`), и агент покажет, кому и что ушло бы, не
отправляя на самом деле.

## 4. Решения и их обоснование

### Транспорт: stdio, а не HTTP

Сервер — дочерний процесс Claude, общение идёт через стандартный ввод-вывод.
Ничего не слушает порт, нечего защищать токеном, нечего ломаться при
перезапуске.

### Библиотека MTProto: GramJS, хотя она архивирована

При установке `telegram` npm выдаёт предупреждение: пакет архивирован,
разработка продолжается в форке `teleproto`. Форк живой и API совместимо, но
он ведётся одним человеком, и он заменил проверенный `@cryptography/aes` на
собственную свежую библиотеку — в том самом коде, через который проходят
ключи шифрования сессии. Архивированный, но многие годы использовавшийся
GramJS в известном стабильном состоянии — риск меньший. Решение не
окончательное и меняется одной строкой в `tg.mjs`.

### Запреты — в коде сервера, а не в промпте

Это то, без чего схема была бы менее безопасной. Когда агент — языковая
модель, системный промпт не гарантия: его можно переосмыслить, и проверить
это постфактум нельзя. Поэтому:

| Проверка | Как работает |
| --- | --- |
| **Сверка получателя** | Чтобы отправить или прочитать, агент обязан передать не только `peer`, но и `expect_title` — имя, которое он ожидает. Сервер спрашивает у Telegram, кто это на самом деле, и отказывается при расхождении |
| **Только человек** | Группы и каналы запрещены. Боты тоже: у бота в диалогах тот же `type: user`, что у человека |
| **Лимиты частоты** | 1 отправка в 5 секунд, 20 в час — общий счётчик для текста и файлов. Защита не от злого умысла, а от зацикливания: за флуд через MTProto банят навсегда |
| **Размер файла** | И `telegram_send_file`, и `telegram_download_file` отказываются работать с файлами больше `TELEGRAM_MCP_MAX_FILE_MB` (по умолчанию 50 МБ) — у скачивания размер известен из метаданных сообщения заранее, так что проверка идёт раньше самого скачивания |
| **Журнал** | Каждая отправка — строкой в `~/.telegram-mcp/sent.log`: когда, кому, что |
| **Сухой прогон** | `TELEGRAM_MCP_DRY_RUN=1` — показывает, что ушло бы, не отправляя |

### Чтение истории — постранично, а не одним запросом

`telegram_read_messages` отдаёт не больше 100 сообщений за вызов. Чтобы
прочитать чат целиком, агент вызывает инструмент повторно с `offset_id` —
id самого старого сообщения из предыдущего ответа минус один — пока ответ не
станет пустым. Это сознательный выбор: один запрос без ограничения размера
мог бы вернуть мегабайты текста за один ход и не даёт возможности остановиться
на середине, если задача решена раньше.

### Скачивание файла — имя из сообщения, но не доверяя ему

`telegram_download_file` сначала запрашивает только метаданные сообщения
(имя файла, MIME-тип, размер), и лишь потом — если размер укладывается в
лимит — собственно скачивает. Имя файла, которое прислал собеседник, —
чужой ввод: сервер вырезает из него путевые разделители (`/` и `\`) и ведущие
точки, чтобы нельзя было подсунуть что-то вроде `../../something`. Если у
файла вообще нет имени (частый случай для фото и голосовых), сервер собирает
своё — по id сообщения и MIME-типу. Если в папке уже есть файл с таким же
именем, новый сохраняется с меткой времени, а не затирает старый.

### Расшифровка голоса — через Premium, с лимитом и таймаутом

Голосовые сообщения и видео-кружки расшифровываются вызовом
`messages.transcribeAudio` — той же функцией Telegram Premium, что в
приложении. Без Premium Telegram может всё равно дать несколько бесплатных
расшифровок (поле `trialRemainsNum` у ответа), после чего откажет понятной
ошибкой. Два технических нюанса:

- Иногда Telegram не присылает текст сразу, а сообщает «готовится» и присылает
  его позже отдельным событием (`UpdateTranscribedAudio`) — сервер ждёт это
  событие до 20 секунд, а если не дождался, сообщает об этом прямо, а не
  зависает.
- Расшифровка — это отдельный сетевой запрос на каждое голосовое. Чтобы один
  вызов `telegram_read_messages` не растянулся на минуты при чате с десятками
  голосовых, за один вызов расшифровывается не больше 5 штук; остальные
  помечаются как пропущенные — агент дочитывает их следующим вызовом.

### Поиск получателя: падежи разбираются кодом, решение остаётся за агентом

«Маше» → «Маша» приводится детерминированно в `match.mjs` и проверяется
тестами, а не угадывается моделью на словах. Работает по основам слов: от
обоих слов отсекается одно падежное окончание и сравниваются остатки. При этом
«Маша» не совпадает ни с «Мишей», ни с «Мариной»: совпадение внутрь слова не
считается. Латиница по гласным не режется — иначе `mike` и `mika` склеились бы
в одно.

Каждый кандидат получает уровень уверенности: `exact` (username или имя
целиком), `stem` (совпала основа), `weak` (основа короче трёх символов).
`telegram_find_recipient` **не выбирает получателя сам** — если кандидатов
больше одного, агент спрашивает владельца. Неоднозначность — нормальный
результат, а не сбой.

### Чужой текст — данные, а не инструкции

Текст сообщений, которые читает `telegram_read_messages` (включая
расшифровки голоса), — это слова собеседника, а не команды агенту. Если там
будет просьба что-то сделать, решает её выполнять или нет владелец аккаунта,
а не отправитель сообщения. Это явно прописано в MCP-инструкциях сервера, а
не оставлено на угадывание моделью.

### Чистота stdout

Для stdio-транспорта stdout — это канал JSON-RPC, и одна посторонняя строка
там рвёт протокол. GramJS по умолчанию пишет в `console.log`. Поэтому
`silence-stdout.mjs` импортируется первым и уводит все `console.*` в stderr, а
логгер GramJS выключен явно. Это проверяется тестом.

### Соединение закрывается само

MTProto-коннект поднимается при первом вызове инструмента и закрывается после
двух минут простоя — висящий коннект с heartbeat-циклами не нужен, пока
обращений нет.

## 5. Переменные окружения

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `TELEGRAM_MCP_DRY_RUN` | выкл | `1` — ничего не отправлять, только показывать, что ушло бы |
| `TELEGRAM_MCP_ALLOW_GROUPS` | выкл | `1` — разрешить группы и каналы (для отправки и чтения) |
| `TELEGRAM_MCP_ALLOW_BOTS` | выкл | `1` — разрешить ботов |
| `TELEGRAM_MCP_MIN_INTERVAL_SEC` | `5` | Минимум секунд между отправками (текст и файлы — общий счётчик) |
| `TELEGRAM_MCP_MAX_PER_HOUR` | `20` | Лимит отправок в час |
| `TELEGRAM_MCP_MAX_FILE_MB` | `50` | Максимальный размер файла для `telegram_send_file` и `telegram_download_file` |
| `TELEGRAM_MCP_HOME` | `~/.telegram-mcp` | Где лежат креды, журнал и состояние лимитов |

## 6. Частые ошибки

| Симптом | Причина | Что сделать |
| --- | --- | --- |
| `npm run check`: «аккаунт ещё не подключён» | Не пройден вход | `npm run login` |
| При входе `PHONE_CODE_EXPIRED` | Код истёк, он живёт недолго | Запустить `npm run login` снова и ввести код быстрее |
| При входе `SESSION_PASSWORD_NEEDED` | Включена двухфакторная авторизация | Скрипт сам спросит пароль — ввести его |
| `FLOOD_WAIT_<n>` при входе | Telegram ограничивает попытки входа на номер, порядка пяти в сутки | Подождать указанные секунды. Не перебирать |
| `AUTH_KEY_UNREGISTERED` при работе | Сессия отозвана: вышел из устройства в Telegram или сменил пароль 2FA | `npm run login` заново |
| «Отказ: peer … — это X, а ты ожидал Y» | Сработала сверка получателя | Так и задумано. Агент перепроверит через `telegram_find_recipient` |
| «Среди N последних диалогов никого похожего нет» | Переписки с этим человеком не было — в диалогах его нет | Назвать по `@username`, либо один раз написать ему из приложения Telegram |
| «Кандидатов 2» и список | Два человека с подходящим именем | Так и задумано. Уточнить, кому именно, или назвать `@username` |
| «Слишком часто» / «лимит 20 сообщений в час» | Сработал лимит частоты | Подождать. Если лимит нужен выше — `TELEGRAM_MCP_MAX_PER_HOUR` |
| «Файл не найден» / «должен быть абсолютным путём» | `telegram_send_file` получил несуществующий или относительный путь | Указать полный путь к файлу на диске |
| «У сообщения нет файла для скачивания» | `telegram_download_file` вызван для сообщения без медиа | Проверить `hasMedia` в ответе `telegram_read_messages` |
| «не расшифровано в этом вызове» | В чате больше 5 голосовых/кружков за один вызов `telegram_read_messages` | Вызвать инструмент ещё раз — он дочитает оставшиеся |
| «расшифровка недоступна» | Либо это не голосовое сообщение, либо закончились бесплатные расшифровки без Premium | Проверить тип сообщения; для безлимита нужен Telegram Premium |
| Claude не видит инструменты | Сервер не зарегистрирован или сессия Claude старше регистрации | `claude mcp get telegram` → должно быть `✔ Connected`. Перезапустить Claude Code |

Где смотреть логи: `npm run check` — состояние целиком; `~/.telegram-mcp/sent.log` —
что уходило; stderr MCP-сервера видно в Claude Code как логи сервера `telegram`.

## 7. Ограничения и риски

Подтверждено документацией Telegram
(<https://core.telegram.org/api/obtaining_api_id>, <https://core.telegram.org/api/auth>):

- **Аккаунты, входящие через неофициальные клиенты API, автоматически ставятся
  под наблюдение** на предмет нарушений условий использования. Этот вход —
  именно такой.
- **За флуд, спам и накрутку аккаунт банится навсегда.** Схема рассчитана на
  единичные личные сообщения; рассылки через неё делать нельзя. Лимиты в
  сервере поставлены исходя из этого.
- **Попытки входа на один номер в сутки ограничены** (порядка пяти). Поэтому
  шаг входа стоит проходить аккуратно, а не перебором.
- **Новая сессия сначала не подтверждена:** остальные твои устройства получат
  уведомление о новом входе и могут его отклонить.
- **Расшифровка голоса без Premium ограничена** бесплатными попытками
  (`trialRemainsNum`), после чего Telegram начнёт отказывать.

Про доступ:

- **Строка сессии равносильна паролю от Telegram.** Кто её получил, читает
  твои чаты и пишет от твоего имени, пока сессию не отозвали. Поэтому она
  лежит только в `~/.telegram-mcp/credentials.json` с правами `0600`, вне
  репозитория, и не печатается ни в вывод, ни в логи.
- **Отозвать доступ:** Telegram → **Settings** → **Devices** → удалить
  сессию. Это надёжнее удаления файла: после отзыва строка сессии мертва где
  угодно.
- **Отключить от Claude Code:** `claude mcp remove telegram -s user`.
- **Удалить с машины:** `rm -rf ~/.telegram-mcp`.

Про область видимости:

- Сервер, зарегистрированный на уровне **пользователя**, доступен агенту из
  любой папки, а не только из этого проекта. Если хочешь сузить до одного
  проекта: `claude mcp remove telegram -s user`, затем
  `claude mcp add telegram -s local -- node <путь>/server.mjs` из нужной папки.
- **`telegram_list_dialogs` видит диалоги, а не адресную книгу**, и не больше
  200 самых свежих. Человека, с которым переписки не было, по имени не найти.
- **Поле `type` не отличает бота от человека.** Поэтому боты запрещены
  отдельной проверкой, а не отсеиваются по типу.
